## 1. 摘要

**MissionOps(探索派遣系统)是独立于挖矿/制造/商业主系统、独立于世界系统的放置类"远征副本"模块**:玩家造船、雇舰长、组编队,把编队派出去接探索/战斗/打捞/护航/信号委托,按现实时间计时,种子掷骰结算,带回探索点、发现物、蓝图碎片、远征材料与小额信用点。

一句话:**玩家亲自挖矿是发动机,MissionOps 是第二台——广度与进度,绝不替代核心体验。**

### 2.2 关键设计决策(实施中确立)

1. **钱包唯一权威 = economy_save.json**(R3 审查结论):GameSave 只挂 missionops 节;MissionOps 每次动钱(雇佣/解雇/结算)立即 `Economy.save_game()` 同步——消灭双写者,关窗零窗口。
2. **崩溃安全结算顺序**(自查 P1):先从 active 删除并同步落盘 → 再给奖励。崩溃时丢奖励(而非双给),通胀方向安全。
3. **节损坏深度校验**:apply 回调返回 bool(false=损坏→挂起写入);校验覆盖全部消费字段(类型+交叉引用+数值合理性)。
4. **启动顺序**:`_startup_catch_up` 用 `call_deferred` 延迟到所有节注册/回放完成后。
5. **测试确定性**:固定 seed(穷举选必胜/必败)+ `reset_state()` 清残留 + 损坏测试自清理。

## 2.6 已知限制(诚实声明)

以下问题**已识别但未完全解决**:

1. **跨档原子性**:雇佣/解雇/结算涉及两个存档文件(missionops + economy),当前用"先存 missionops(检查)→再动钱"的顺序保证**失败方向反通胀**(玩家丢失而非多得),但两次保存之间仍有窗口——M2 需引入事务 ID 或恢复日志。
2. **测试中的损坏模拟**:通过直接篡改 JSON 文件模拟,真实磁盘损坏不一定长这样。
3. **UI 私有方法访问**:测试中 `mo._ui._one_click_prep()` 穿透了封装。

## 3. 架构与独立性(不变)

```
Economy(hive_level() / add_money / save_game)
   ▲ 单向依赖(动钱即同步)
MissionOps(状态机/任务板/编队/舰长/结算)
   │ 信号:mission_completed / captain_state_changed / board_refreshed
   ▼ 想听的人听
WorldState(零依赖;M4 适配器注入)
```

存档架构:
- **economy_save.json** = Economy 全量(钱包唯一权威)
- **save.json** = GameSave(missionops 节;原子写 tmp+rename)
- 两档通过"动钱即同步 Economy.save_game()"保持一致

## 4. 游戏内验证步骤(M1)

1. 打开项目,进入游戏
2. 点击空间站 → 建造面板 → 应看到**「雇佣兵巢穴」**卡片(与机库/建造厂并列)
3. 建造 Lv1(材料:普矿A×300 + 密封舱体×2,工期 300s÷建造速度倍率)
4. 按 **F6** → 任务板打开
5. 点「一键备战」(自动雇首名候选 + 建一队)
6. 选任意任务 → 点「派遣」
7. 等任务时长到点 → 战报显示(成功:EP+₡ / 失败:无奖励)
8. 再按 F6 可继续派遣或等待招募池刷新

未建巢穴时 F6 任务板显示:"编队: [需要雇佣兵巢穴]——空间站建造解锁探索派遣"。
